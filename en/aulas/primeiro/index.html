02 · The project for your first loop

One folder, one test file frozen by hash, and not a single line of the function. The agent writes the function.

Terminal · create the folder and freeze the tests
mkdir -p ~/ensaio-loop/conta/tests && cd ~/ensaio-loop/conta && git init -q
# paste the test file from the next block into tests/test_conta.py, then:
sha256sum tests/test_conta.py > tests.sha256
git add -A && git commit -qm "testes congelados"
python3 -m pytest -q -p no:cacheprovider tests/ | tail -1   # still fails: conta.py does not exist

Claude Code · the /goal condition (level 3, with a cap)
/goal python3 -m pytest -q -p no:cacheprovider tests/ prints 6 passed, sha256sum -c tests.sha256 prints OK and git diff --exit-code -- tests/ exits with code 0, with all three outputs printed in the conversation, or stop after 8 turns
Terminal · you check it, without trusting the summary
cd ~/ensaio-loop/conta
python3 -m pytest -q -p no:cacheprovider tests/ | tail -1
sha256sum -c tests.sha256
git diff --exit-code -- tests/; echo "rc=$?"
loop-codex.sh · the same loop with codex exec (exercise 3)
#!/usr/bin/env bash
# Your own loop: at most 3 cycles of codex exec; the three commands decide when to stop.
set -u
cd ~/ensaio-loop/conta
passes() {
  python3 -m pytest -q -p no:cacheprovider tests/ 2>&1 | tail -1 | grep -q '^6 passed' &&
  sha256sum -c --quiet tests.sha256 &&
  git diff --quiet -- tests/
}
for ciclo in 1 2 3; do
  if passes; then echo "PRONTO no ciclo $((ciclo - 1))"; exit 0; fi
  echo "ciclo $ciclo: codex exec"
  timeout 15m codex exec --sandbox workspace-write \
    "Crie conta.py com conta_palavras(texto) que faça os testes de tests/ passarem. Não altere nada em tests/."
done
if passes; then echo "PRONTO no ciclo 3"; exit 0; fi
echo "PARADO: teto de 3 ciclos"; exit 2
Example from the repository

With the same condition, in headless mode (claude -p "/goal …"), the agent wrote conta.py and finished by printing:

- python3 -m pytest -q -p no:cacheprovider tests/ → 6 passed in 0.01s
- sha256sum -c tests.sha256 → tests/test_conta.py: OK
- git diff --exit-code -- tests/ → saiu com código 0

Its function and yours may be different; what has to match are the three outputs.

$ echo "def test_x(): pass" > tests/test_conta.py
$ sha256sum -c tests.sha256
tests/test_conta.py: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
$ echo $?
1

Swapping the test for an empty one would make pytest pass, but the hash and the git diff flag it. That's the difference between level 2 and level 3.

  • Objective: the /goal condition.
  • State: the files and the tests commit.
  • Action: the agent editing conta.py.
  • Verification: pytest with a count, hash and git diff, printed in the conversation.
  • Stop: the /goal evaluator or the 8-turn cap.

03 · Practice

On your machine. Exercise 2 uses little of your quota.

E1 · The project ready for the loop

10 min

Create the folder, the test file, the hash and the first commit. Run pytest before the function exists.

Done when: sha256sum -c tests.sha256 → tests/test_conta.py: OK, git log --oneline | wc -l → 1, and pytest still fails (the function doesn't exist).

E2 · The first loop running

15 min

Open Claude Code in the folder and paste the /goal condition. Let it run without interfering; if Claude asks permission to run pytest, approve it.

Done when: The goal status shows the condition met, and the three check commands, run by you, give 6 passed, tests/test_conta.py: OK and rc=0.

E3 · The same loop with Codex

15 min

Delete conta.py and run the same request through codex exec with a write sandbox, using the loop-codex.sh from the block above: at most 3 cycles, stopping when the three commands pass.

Done when: Your loop ends before the 3rd cycle, and the same three commands give 6 passed, OK and rc=0; git diff --stat -- tests/ comes out empty.
