02 · O projeto do primeiro loop

Uma pasta, um arquivo de testes congelado por hash e nenhuma linha da função. Quem escreve a função é o agente.

Terminal · criar a pasta e congelar os testes
mkdir -p ~/ensaio-loop/conta/tests && cd ~/ensaio-loop/conta && git init -q
# cole o arquivo de testes do próximo bloco em tests/test_conta.py, depois:
sha256sum tests/test_conta.py > tests.sha256
git add -A && git commit -qm "testes congelados"
python3 -m pytest -q -p no:cacheprovider tests/ | tail -1   # ainda falha: conta.py não existe
tests/test_conta.py
from conta import conta_palavras


def test_vazio():
    assert conta_palavras("") == 0


def test_uma():
    assert conta_palavras("loop") == 1


def test_espacos_repetidos():
    assert conta_palavras("  o   loop  para ") == 3


def test_quebra_de_linha_e_tab():
    assert conta_palavras("objetivo\nestado\tação") == 3


def test_pontuacao_nao_e_palavra():
    assert conta_palavras("pronto , quando - passa") == 3


def test_acentos():
    assert conta_palavras("verificação e parada") == 3
Claude Code · a condição do /goal (nível 3, com teto)
/goal python3 -m pytest -q -p no:cacheprovider tests/ imprime 6 passed, sha256sum -c tests.sha256 imprime OK e git diff --exit-code -- tests/ sai com código 0, com as três saídas impressas na conversa, ou pare depois de 8 turnos
Terminal · você confere, sem acreditar no resumo
cd ~/ensaio-loop/conta
python3 -m pytest -q -p no:cacheprovider tests/ | tail -1
sha256sum -c tests.sha256
git diff --exit-code -- tests/; echo "rc=$?"
Exemplo do repositório

Com a mesma condição, em modo sem interface (claude -p "/goal …"), o agente escreveu conta.py e terminou imprimindo:

- python3 -m pytest -q -p no:cacheprovider tests/ → 6 passed in 0.01s
- sha256sum -c tests.sha256 → tests/test_conta.py: OK
- git diff --exit-code -- tests/ → saiu com código 0

A função dele e a sua podem ser diferentes; o que tem de bater são as três saídas.

$ echo "def test_x(): pass" > tests/test_conta.py
$ sha256sum -c tests.sha256
tests/test_conta.py: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
$ echo $?
1

Trocar o teste por um vazio faria o pytest passar, mas o hash e o git diff acusam. É a diferença entre o nível 2 e o nível 3.

  • Objetivo: a condição do /goal.
  • Estado: os arquivos e o commit dos testes.
  • Ação: o agente editando conta.py.
  • Verificação: pytest com contagem, hash e git diff, impressos na conversa.
  • Parada: o avaliador do /goal ou o teto de 8 turnos.

03 · Prática

Na sua máquina. O exercício 2 gasta pouco da sua cota.

E1 · O projeto pronto para o loop

10 min

Crie a pasta, o arquivo de testes, o hash e o primeiro commit. Rode o pytest antes de existir a função.

Pronto quando: sha256sum -c tests.sha256 → tests/test_conta.py: OK, git log --oneline | wc -l → 1, e o pytest ainda falha (a função não existe).

E2 · O primeiro loop rodando

15 min

Abra o Claude Code na pasta e cole a condição do /goal. Deixe rodar sem interferir; se o Claude pedir permissão para rodar o pytest, aprove.

Pronto quando: O status do goal mostra a condição atingida, e os três comandos de conferência, rodados por você, dão 6 passed, tests/test_conta.py: OK e rc=0.

E3 · O mesmo loop com o Codex

15 min

Apague conta.py e rode o mesmo pedido pelo codex exec com sandbox de escrita, num laço seu de no máximo 3 ciclos que para quando os três comandos passam.

Pronto quando: Seu laço termina antes do 3º ciclo, e os mesmos três comandos dão 6 passed, OK e rc=0; git diff --stat -- tests/ sai vazio.
