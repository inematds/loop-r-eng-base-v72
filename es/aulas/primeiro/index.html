Clase 8 · 20 min

Tu primer loop: objetivo pequeño con criterio nivel 3

Es hora de juntar las piezas en un loop de verdad, pequeño a propósito: una función para contar palabras, seis tests congelados con hash y una condición de /goal nivel 3 con tope de turnos. Lo bastante pequeño para terminar en minutos; lo bastante completo para tener las cinco piezas. Al final, el mapa de la formación y tu plan con fechas.

Empezar la lección

En esta lección vas a

  1. 1Montar el proyecto con tests congelados y hash
  2. 2Escribir la condición del /goal en el nivel 3, con tope
  3. 3Verificar por tu cuenta, sin creer en el resumen
  4. 4El mapa de los seis cursos y tu plan con fechas

Objetivo: correr tu primer loop con /goal en un proyecto pequeño, con tests congelados, criterio nivel 3 y tope de turnos, y salir con el plan de la formación.

02 · El proyecto del primer loop

Una carpeta, un archivo de pruebas congelado por hash y ninguna línea de la función. Quien escribe la función es el agente.

Terminal · crear la carpeta y congelar las pruebas
mkdir -p ~/ensaio-loop/conta/tests && cd ~/ensaio-loop/conta && git init -q
# pega el archivo de pruebas del próximo bloque en tests/test_conta.py, después:
sha256sum tests/test_conta.py > tests.sha256
git add -A && git commit -qm "testes congelados"
python3 -m pytest -q -p no:cacheprovider tests/ | tail -1   # todavía falla: conta.py no existe

Claude Code · la condición del /goal (nivel 3, con tope)
/goal python3 -m pytest -q -p no:cacheprovider tests/ imprime 6 passed, sha256sum -c tests.sha256 imprime OK e git diff --exit-code -- tests/ sai com código 0, com as três saídas impressas na conversa, ou pare depois de 8 turnos
Terminal · tú lo verificas, sin creer en el resumen
cd ~/ensaio-loop/conta
python3 -m pytest -q -p no:cacheprovider tests/ | tail -1
sha256sum -c tests.sha256
git diff --exit-code -- tests/; echo "rc=$?"
loop-codex.sh · el mismo loop con codex exec (ejercicio 3)
#!/usr/bin/env bash
# Laço seu: no máximo 3 ciclos de codex exec; quem decide parar são os três comandos.
set -u
cd ~/ensaio-loop/conta
passes() {
  python3 -m pytest -q -p no:cacheprovider tests/ 2>&1 | tail -1 | grep -q '^6 passed' &&
  sha256sum -c --quiet tests.sha256 &&
  git diff --quiet -- tests/
}
for ciclo in 1 2 3; do
  if passes; then echo "PRONTO no ciclo $((ciclo - 1))"; exit 0; fi
  echo "ciclo $ciclo: codex exec"
  timeout 15m codex exec --sandbox workspace-write \
    "Crie conta.py com conta_palavras(texto) que faça os testes de tests/ passarem. Não altere nada em tests/."
done
if passes; then echo "PRONTO no ciclo 3"; exit 0; fi
echo "PARADO: teto de 3 ciclos"; exit 2
Ejemplo del repositorio

Con la misma condición, en modo sin interfaz (claude -p "/goal …"), el agente escribió conta.py y terminó imprimiendo:

- python3 -m pytest -q -p no:cacheprovider tests/ → 6 passed in 0.01s
- sha256sum -c tests.sha256 → tests/test_conta.py: OK
- git diff --exit-code -- tests/ → saiu com código 0

Su función y la tuya pueden ser diferentes; lo que tiene que coincidir son las tres salidas.

$ echo "def test_x(): pass" > tests/test_conta.py
$ sha256sum -c tests.sha256
tests/test_conta.py: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
$ echo $?
1

Cambiar la prueba por una vacía haría que pytest pasara, pero el hash y el git diff lo delatan. Es la diferencia entre el nivel 2 y el nivel 3.

  • Objetivo: la condición del /goal.
  • Estado: los archivos y el commit de las pruebas.
  • Acción: el agente editando conta.py.
  • Verificación: pytest con conteo, hash y git diff, impresos en la conversación.
  • Parada: el evaluador del /goal o el tope de 8 turnos.

03 · Práctica

En tu máquina. El ejercicio 2 gasta poco de tu cuota.

E1 · El proyecto listo para el loop

10 min

Crea la carpeta, el archivo de pruebas, el hash y el primer commit. Corre pytest antes de que exista la función.

Listo cuando: sha256sum -c tests.sha256 → tests/test_conta.py: OK, git log --oneline | wc -l → 1, y pytest todavía falla (la función no existe).

E2 · El primer loop corriendo

15 min

Abre Claude Code en la carpeta y pega la condición del /goal. Déjalo correr sin interferir; si Claude pide permiso para correr pytest, apruébalo.

Listo cuando: El estado del goal muestra la condición alcanzada, y los tres comandos de verificación, corridos por ti, dan 6 passed, tests/test_conta.py: OK y rc=0.

E3 · El mismo loop con Codex

15 min

Borra conta.py y ejecuta el mismo pedido con codex exec con sandbox de escritura, usando el loop-codex.sh del bloque de arriba: máximo 3 ciclos, parando cuando los tres comandos pasan.

Listo cuando: Tu ciclo termina antes de la 3.ª vuelta, y los mismos tres comandos dan 6 passed, OK y rc=0; git diff --stat -- tests/ sale vacío.
